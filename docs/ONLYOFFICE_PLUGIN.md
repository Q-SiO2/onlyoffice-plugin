# ONLYOFFICE Desktop Presentation plugin

Official documentation was reviewed on **2026-10-01**. The plugin uses the current `type: "panelRight"`, `EditorsSupport: ["slide"]`, `initDataType: "none"`, a stable `asc.{UUID}` GUID and local `index.html`. The deprecated `isInsideMode`, `isVisual`, `isModal`, `menu` and manifest `events` fields are omitted. Minimum declared editor version is 8.3.0. Current installed editor is 9.3.1.8.

## Files and lifecycle

`config.json` registers the sidebar. `src/main.tsx` mounts the shared React presenter in `Asc.plugin.init`, implements the Office API bridge, and handles `Asc.plugin.button` for closure. `window.html` / `src/window.tsx` render a public projector view inside an official `Asc.PluginWindow`, without passing presenter credentials in the URL. QR/result windows contain only backend address, public session UUID and view mode.

`vendor/plugins.js` is an unmodified, locally bundled SDK snapshot; provenance and SHA-256 are in [THIRD_PARTY.md](THIRD_PARTY.md). Bundling avoids CDN failure during a LAN demo. `app.js`, `window.js` and their styles are generated by esbuild under `onlyoffice-plugin/dist`. Root icons are generated geometric PNGs.

## Build, package, install

```powershell
npm ci
npm run build
npm run package:plugin
```

The package script ZIPs the **contents** of `onlyoffice-plugin/dist` into `dist/paloalto-live.plugin`, with `config.json` at its archive root, not inside a parent folder.

1. Open a presentation, then **Plugins → Plugin Manager → My plugins**.
2. Click **Install plugin manually** and choose `dist/paloalto-live.plugin`.
3. Click **Plugins → Palo Alto Live**.
4. Enter the backend URL, e.g. `http://localhost:3000` for development, and presenter key. The public web URL can be different from this API URL in development.

Official folder alternative on Windows:

```text
%LOCALAPPDATA%\ONLYOFFICE\DesktopEditors\data\sdkjs-plugins\{A7E2C42A-3184-4E8B-9477-893BC54F8591}\
```

Place the built plugin contents in that GUID folder and restart the app or reopen the editor. On macOS: `~/Library/Application Support/asc.onlyoffice.ONLYOFFICE/data/sdkjs-plugins`; Linux: `~/.local/share/onlyoffice/desktopeditors/sdkjs-plugins`. Do not alter the default plugin folders. For updates, remove/reinstall only Palo Alto Live via Plugin Manager, or replace only this custom GUID folder's contents after closing the plugin. User installation and package instructions follow [official adding-plugins docs](https://api.onlyoffice.com/docs/desktop-editors/usage-api/adding-plugins/).

## Network/CORS

Fetch and Socket.IO go directly to your backend. OPTIONS preflight must return 204/200 and allow `Authorization, Content-Type`, `GET, POST, DELETE, OPTIONS`. The backend checks exact origins for both HTTP and WebSocket upgrades; it never reflects arbitrary origins or uses wildcard credentialed CORS.

The current [official AI networking guide](https://api.onlyoffice.com/docs/ai/guides/custom-providers/) describes `onlyoffice://plugin`. **Observed compatibility difference:** 9.3.1.8 loads the installed local plugin from `file:///.../sdkjs-plugins/...`, which sends the opaque `Origin: null` on browser requests. The sample allowlist includes `null` for those legacy builds. Opaque origins cannot uniquely identify ONLYOFFICE: this widens which local/sandboxed pages can make requests, so bearer authentication remains mandatory. Remove `null` if your actual editor uses the newer scheme. If connection fails, inspect the actual origin and configure it; do not disable browser security.

Use HTTPS for public servers. No administrative key appears in packaged files. The presenter types it once; the dashboard uses a short-lived token in memory. Backend URL alone is saved in localStorage.

## Slide interaction

The current slide is accessed inside documented `Asc.plugin.callCommand` using `Api.GetPresentation().GetCurrentSlide()`. Results are generated as 1600×900 PNGs; QR images are square. The bridge passes Base64 image data and its ratio through `Asc.scope`, computes an aspect-preserving size in EMU from `GetWidth`/`GetHeight`, creates the image with `Api.CreateImage`, centers it, and calls `slide.AddObject`.

No `RemoveAllObjects`, object replacement or slide deletion is called. Existing content is preserved; use a blank slide to avoid obscuring it. Inserted images are snapshots, not live charts; reinsertion adds another image. Use Ctrl+Z or move/delete the image normally. The callback confirms completion, with a timeout that warns against blindly repeating an insertion.

The plugin does not inspect or manipulate the editor DOM. Its own React DOM is normal plugin content. Scene selection is independent of the current slide. No API request attempts to infer a scene from video playback.

## Slideshow and events

The [documented Presentation events](https://api.onlyoffice.com/docs/plugins/interacting-with-editors/presentation-api/Events/) include slide changes and slideshow begin/end. New event subscriptions should use `attachEditorEvent`, rather than manifest event declarations. This v1 deliberately uses manual controls; no event subscriptions are required for polling.

No reliable documented embedded-video playback-ended callback was found in the reviewed event surface. This is a documented research finding, not a claim that internal video hooks do not exist. Manual close/open controls are the reliable alternative. Slideshow methods exist, but the sidebar is an edit-mode control surface and may not remain accessible over a full-screen show. Have a teammate use `/presenter`, or exit slideshow to manage interactions. Insert snapshots in **edit mode**, then resume the show. A live projector browser or large plugin window can show aggregates; a plugin window may not overlay a full-screen slideshow on every OS.

## Debugging

Close the app normally, then launch in debug mode:

```powershell
& 'C:\Program Files\ONLYOFFICE\DesktopEditors\DesktopEditors.exe' --ascdesktop-support-debug-info
```

Use F12 (or F1/Inspect Element depending on editor context) and select the plugin iframe in DevTools. Check JavaScript errors, OPTIONS responses and Socket.IO connectivity. Do not print tokens/phone inputs. See [official desktop plugin debugging](https://api.onlyoffice.com/docs/plugins/development-workflow/debugging/for-desktop-editors/). Rebuild after source changes and reinstall/reopen the plugin. The browser presenter is a fallback if an editor update causes trouble.
